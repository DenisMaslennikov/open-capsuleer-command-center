# Database schema contract

Whoever builds a feature slice here implements tables that are already declared. The schema is
not a by-product of tasks: if every task invents its own tables, a month later the same concept
lives in three caches under three names, the migration graph forks, and the right to be forgotten
only reaches half of the rows.

## What is in this directory

| File | What it is | Edited by |
|---|---|---|
| `schema.json` | the contract: every aggregate, table, column, type, key, index and cascade rule | a human, through a PR |
| `schema.dbml` | the same contract as a diagram for <https://dbdiagram.io> | generated |

`schema.json` is canonical. `schema.dbml` is derived: edit the contract and regenerate, never the
other way round. A single aggregate's slice is extracted by the same tooling when a task starts
(`schema_design.py --slice <aggregate>`); slices are not committed, so there is no second copy to
drift.

The contract is produced and regenerated by the cascade pipeline tooling, which lives outside this
repository (see ADR-0002 on what belongs in the repository and what does not):

```
~/.config/cascade/bin/schema_design.py --project occc --reemit <path>/schema.json
```

## Aggregates

One aggregate is one module `backend/src/app/dbhelpers/<aggregate>.py` and one owner of its tables.

`cache` rows are disposable.

## Conventions the contract encodes

- Primary keys are `bigint identity` for our tables; SDE tables use the game id as the key.
- Game identifiers (`type_id`, `character_id`, `corporation_id`, `structure_id`, `alliance_id`,
  `eve_*_id`) are `bigint` without a foreign key: a reimport of static data must never lock or
  rewrite user rows, so user tables do not reference SDE by foreign key at all.
- Ownership is two nullable foreign keys plus `CHECK num_nonnulls(...) = 1`; a polymorphic
  `entity_id`, EAV tables and a universal `attributes` column are banned.
- Money is `numeric(20,2)`, quantities and skill points are `numeric(20,0)` or `bigint`; floating
  point is banned for both.
- Time is `timestamptz` in UTC.
- `jsonb` is allowed only for opaque external payloads (`esi_responses.body`,
  `notification_events.payload`).
- Secrets (refresh tokens, webhooks, phone numbers) are `bytea` columns named `*_encrypted`.
- Every synchronised table has a unique key for upsert (owner plus game id); synchronisation is
  idempotent: upsert, then delete the owner's rows that the response no longer contains.
- Missing access (a scope or a corporation role) is a row in `sync_states` with a `skip_reason`,
  not a missing row: otherwise "no access" is indistinguishable from "no data".
- Corporate data is stored per account (`corporations.account_id`), not in shared rows.
- Partitioning applies only to `market_data`, by time.

## Diagram

`schema.dbml` imports into <https://dbdiagram.io> as is. The `TableGroup` blocks that group tables
by aggregate are a **paid** feature of that service; without them the diagram is one flat set of
67 tables. The free variant is produced by the same generator with `--no-groups`. The diagram is
for reading only — the contract and the migrations are the source of truth.

## Change process

1. Change the contract first, then the models, then the migration — in one PR.
2. A PR that edits `schema.json` is `review:human`; the contract does not merge on an agent's
   approval.
3. Migrations stay linear: one revision per task, `alembic heads` is one head, `alembic merge` is
   banned because it silences a conflict instead of resolving it.
4. Two tasks never own the same table; parallel work is allowed only on disjoint table sets.

## Known deviations

- Descriptive strings in `schema.json` (`purpose`, `comment`, `growth`) are in Russian, while the
  repository documents in English. Structural fields are language-neutral. Regenerating the
  contract with English descriptions is a follow-up, not a blocker.
